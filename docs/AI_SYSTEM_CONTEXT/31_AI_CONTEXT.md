# 31 — AI Context

Read this first if you are an AI assistant working in this repository.

## What this system is
See `00_EXECUTIVE_OVERVIEW.md`. TL;DR: React 18 + Vite + Supabase healthcare clinic platform, RC2 in production, canonical bundle-based RBAC active, Phase C blocked.

## What you must never modify (hard rules)
- `AuthorizationService` and everything under `src/lib/authz/` runtime behavior.
- `authz_*` tables, `role_permissions`, `user_roles`, `has_role()`.
- Any SECURITY DEFINER function.
- Any RLS policy.
- Edge Functions unless the user explicitly asks and provides a governance ticket.
- `src/integrations/supabase/client.ts` and `types.ts` (auto-generated).
- `.env` Supabase vars; `supabase/config.toml`.
- Feature-flag defaults for authorization.
- Bundle contents.
- Permission catalog rows.

## How permissions work
```ts
const { authz, loading } = useAuthorization("MyComponent");
if (authz.can("invoices.create")) { ... }
```
- Prefer declarative gates (`<Can>`, `<CanExport>`, `<PermissionRoute>`).
- Never write `role === "admin"` or `roles.includes("admin")` in components.
- Never hit `role_permissions` directly; go through the service.

## How modules interact
- Cross-module reads are OK.
- Cross-module writes should go through a single aggregate root's mutation hook, or a SECURITY DEFINER RPC when multi-table atomicity is required.
- Reporting and Audit are read-only consumers.

## How to design new features
1. Confirm bounded context; extend the right aggregate.
2. Check the permission catalog — reuse existing keys where possible.
3. If a new permission is needed, open a governance ticket first.
4. Migration template:
   ```sql
   CREATE TABLE public.new_table (...);
   GRANT SELECT, INSERT, UPDATE, DELETE ON public.new_table TO authenticated;
   GRANT ALL ON public.new_table TO service_role;
   ALTER TABLE public.new_table ENABLE ROW LEVEL SECURITY;
   CREATE POLICY ... ;
   ```
5. Frontend: use TanStack Query + Supabase client; wrap UI in `<Can>`.
6. Tests: unit (Vitest) + Playwright shadow when authz-relevant.

## Naming conventions
- Files: `PascalCase.tsx` for components, `camelCase.ts` for utilities.
- Hooks: `useXxx`.
- Permissions: `<group>.<verb>[.<qualifier>]`.
- DB columns: `snake_case`.
- Types generated by Supabase — never hand-edit.

## Folder conventions
- Pages grouped by module under `src/pages/<module>/`.
- Shared logic under `src/lib/`.
- Contexts under `src/contexts/`.
- Hooks under `src/hooks/` (or `src/lib/authz/` for authz).

## When in doubt
- Search the docs (`docs/`) first.
- Ask for clarification before changing authorization or schema.
- Prefer additive changes; avoid renaming or deleting public symbols.
