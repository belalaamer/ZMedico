# Portal activation recovery UI — ZMED-220 / ZMED-261

Candidate based on published main c250a552. Client changes only; no SQL, Edge, role or RLS changes. Do not treat this source package as approval to activate the unfinished portal backend or provider integrations.

## Behavior

Retain confirmation of a successful password update for the exact current account. If activation fails or its reply is lost, show activation-only retry and do not repeat Auth updateUser. Unknown password-update outcome has a separate reconciliation state. Ignore results across identity changes/unmount and prevent overlapping submissions. Account/snapshot state belongs to the current identity.

ZMED-261 (P3): real mobile screenshots exposed vertically compressed username/optional-password inputs in the column flex layout. Their existing h-10 intent was overridden by flex:1 shrinking. Keep a40px minimum/nonshrinking input height and apply flexible growth at the desktop breakpoint. No operation or permission change.
