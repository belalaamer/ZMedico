# T1 migration histories

This directory holds **two separate histories**. They are not two halves of one
history, and they must never be copied into one build directory.

| History | Manifest | Records | Version order |
|---|---|---:|---|
| Repository | `repo-history.json` | 436 | repository file versions |
| Production | `production-history.jsonl` | 486 | Production `schema_migrations` versions |

`production/sql/` contains the exact Production statements for the two
same-version conflicts. It is not a replacement for the repository editions.

`repo-annotations.json` records decisions about token-identical repository
files. It has two groups:

- `20260503000512` / `20260503000555`: **unresolved**. Production has one row
  (`20260503000554`) whose SQL matches both. A human must decide whether these
  are one migration recorded twice or two deliberate applications.
- `20260826030000` / `20261025090000`: **intentional re-application**. The same
  coverage `REVOKE`/`GRANT` is applied at two deliberate points; both files
  remain in the repository plan.

Run the fail-closed preflight before any build:

```bash
python3 tools/t1/history_preflight.py --history repo --repo . --expect 436
python3 tools/t1/history_preflight.py --history production --repo . --expect 486
```

At the reviewed commit both commands exit 2: the repository pair above and
Production row `20260503000554` are unresolved. That is the intended result.
The preflight does not choose a candidate, deduplicate a re-application, or
overwrite a source.

The manifests are generated by `tools/t1/build_history_manifests.py` from the
read-only Production export and the repository tree. The build itself never
infers a source at runtime.
